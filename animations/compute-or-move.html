Compute or Move?

How fast an operation runs depends on how much work it does for every byte it moves. Two limits, measured on our cluster, predict where each operation lands.

    About the measurements

    CPU. haskell (AMD EPYC 9755), a 4-CPU batch job like the ones of Exercise 2, NumPy in float64, as in Exercise 1. Each time is the best of 7 repeats with timeit (job 25134, 27 October 2026). The vectors have 10 million numbers (80 MB each), more than the caches hold.

    Bytes moved are the least an operation must read and write: every input once, the result once. a + b reads 160 MB and writes 80 MB. A real program can move more (temporary arrays, cache misses), never less.

    The limits are the best this job measured, not the hardware's data sheet. Memory: a 4,000 × 4,000 matrix times a vector, which reads the 128 MB matrix with 4 threads. Compute: a 4,000 × 4,000 matrix product. A chart like this is called a roofline: no point can go above the roof.

    GPU. fortran, the node of the GPU page (an NVIDIA RTX PRO 6000 Blackwell), in float64 so it compares with the CPU. The GPU's memory limit is a + b on 500 million numbers; smaller arrays fit in the GPU's cache and read faster. The PCIe limit is copying in and back out, both ways, for the largest arrays. Here the matrix product multiplies two different matrices, a @ b, as on the GPU page.
