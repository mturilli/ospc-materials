Choosing a Time Slice, Step by Step

Five processes share one core in round robin, and each switch costs 0.1ms. Which slice keeps both the switching and the wait small?

All steps

    About the model

    One core runs five processes, P1 to P5, in round robin. All of them are ready and none of them waits for I/O or finishes, so each one runs for a whole slice and then goes to the back of the queue. Each context switch costs 0.1ms: the OS saves the registers of one process, loads those of the next, and runs the scheduler (Lecture 11).

    Switching. Every slice of work is followed by one switch, so the share of the core spent switching is switch / (slice + switch). With 0.1ms slices: 0.1 / 0.2 = 50%. With 10ms: 0.1 / 10.1, about 1%. With 1s: 0.1 / 1000.1, about 0.01%.

    P1's wait. After its slice, P1 waits while P2 to P5 run theirs, with a switch before each of them and one more back to P1: 4 slices and 5 switches. With 0.1ms slices: 0.9ms. With 10ms: 40.5ms. With 1s: about 4s.

    One round. Each row is one round, from P1's start until P1 runs again: 1ms, 50.5ms and about 5s. The rows have their own time scales, so that each round fills the width. In the 10ms and 1s rows a switch is too short to see at that scale; it is drawn as a thin line, so you can see where it is.

    Lecture 11 used 1ms per switch. Only the ratio of the slice to the switch matters for the share: 10ms slices with 0.1ms switches lose the same 1% as 100ms slices with 1ms switches. A real switch also leaves the next process with cold caches, so it costs more than the switch itself; the question gives 0.1ms, and so does this page.
